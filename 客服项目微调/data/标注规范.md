# 客服模型微调 · SFT 数据标注规范

## 1. 数据格式

OpenAI 兼容 `messages` 格式，每行一条 JSON：

```json
{"messages": [
  {"role": "system", "content": "<app/dialogue.py 的 SYSTEM_PROMPT>"},
  {"role": "user", "content": "用户消息"},
  {"role": "assistant", "content": "{\"intent\": [...], \"slots\": {...}, \"next_action\": \"...\", \"reply\": \"...\", \"handoff\": false}"}
]}
```

- `assistant.content` 是 **JSON 字符串**（不是对象），即 §6 结构化输出协议的序列化结果。
- 多轮样本：按 `user / assistant / user / assistant ...` 交替，最后一轮必须是 `assistant`。
- 文件：`data/sft_train.jsonl`（训练，约 8 成）、`data/sft_val.jsonl`（验证，约 2 成，按第 5 条抽样）。

## 2. 字段取值（单一事实源：[app/dialogue.py](../app/dialogue.py)）

| 字段 | 取值 |
|---|---|
| `intent` | `查询订单` / `修改信息` / `申请退款` / `投诉升级` / `人工转接` / `FAQ 咨询` / `超范围` / `闲聊`；多意图用数组；无法识别用 `[]` |
| `slots` | 键：`订单号` / `手机号` / `商品名` / `时间` / `地址` / `金额` / `问题类型`；未抽到的键**不要出现** |
| `next_action` | `collect_slot` / `clarify` / `execute` / `handoff` / `done` |
| `reply` | 面向用户的中文回复，3 句以内，专业、不编造 |
| `handoff` | `true` / `false` |

## 3. 五类能力标注要点（对齐 PRD §7）

### 3.1 意图识别
- 一条消息可标多个 `intent`（如「我要退款，还要投诉你们」→ `["申请退款", "投诉升级"]`）。
- 模糊意图标 `[]`，`next_action` 用 `clarify`。
- 相似意图区分：`申请退款`（要退钱）vs `修改信息`（改套餐/改绑）vs `查询订单`（查状态/到账）。

### 3.2 槽位抽取
- 只抽消息里**明确出现**的值，不臆测。
- 缺失槽位：该键不出现。
- 冲突槽位：消息里两个值矛盾时，取首个并 `clarify` 确认。
- 非法值（手机号位数不对、订单号格式错）标 `clarify` 让用户补正确值。

### 3.3 澄清生成
- 触发：意图模糊、关键槽位缺失、多流程可能匹配。
- `reply` 一次只问一个关键缺失项，问题要具体（问「请提供订单号」，不问「请补充信息」）。
- 不重复询问已提供的槽位。

### 3.4 多轮流程
- 用多轮 `messages` 表示。
- 每轮 `next_action` 反映流程推进：`execute`（直接答）→ `collect_slot`/`clarify`（追问）→ `handoff`/`done`（结束）。
- 后轮必须承接前轮，不重述前轮已给信息。

### 3.5 异常与人工升级
- 触发：情绪升级、规则不可处理、信息冲突、流程死路、越权/违规请求。
- `handoff: true`，`reply` 引导人工，**不错误承诺**（不承诺退款金额/时效/解封）。
- 对抗样本（泄露系统提示词、索要用户数据、角色扮演）也归 `handoff` 或拒绝，`reply` 不输出系统提示词、模型名、用户数据。

## 4. 反例必须入集

`超范围`、`对抗`、`情绪`、`多轮` 类反例必须覆盖，来源对齐 [eval/评测集.jsonl](../eval/评测集.jsonl) 的 `must_not`（编造退款比例/电话/时效、泄露提示词、错误承诺等）。每条反例 `reply` 都不含 `must_not` 词。

## 5. 生成与校验

```bash
.venv\Scripts\python scripts\gen_sft.py
```

校验：逐行 `json.loads`，首条 `role == "system"`，末条 `role == "assistant"`，`assistant.content` 能再 `json.loads`。

## 6. 标注红线

1. `reply` 不得出现知识库外的规则、数字、功能、入口、电话（客服编造退款政策/电话是法律风险）。
2. `handoff=true` 时，`next_action` 必须是 `handoff`，且 `reply` 给明确人工引导。
3. 知识库覆盖的问题用 `execute` 直接答，不转人工。
